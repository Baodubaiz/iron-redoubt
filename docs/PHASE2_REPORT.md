# Phase 2 Report — Core Playable Prototype

Status: **Implemented and tested. Awaiting approval before Phase 3.**
Engine: Godot 4.7.2 (GL Compatibility). Date: 2026-11-11.

## How to run

```bash
# Play (desktop window, main menu -> Level 1 / Level 2)
"C:/code/godot/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe" --path .

# Automated tests (headless)
"C:/code/godot/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe" --headless --path . -s res://tests/run_tests.gd

# Screenshots (renders real frames)
"C:/code/godot/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe" --path . -s res://tools/capture.gd -- --out=<folder>
```

You can also open the project in the Godot editor and press F5.

**Controls (mouse = touch):**
- **Drag** a tower from the right palette onto the map. The ghost floats above the finger. Dropping it back on the palette cancels.
- **Tap** a palette button, then tap the map. Tap again to reposition, then press **Build** or **Cancel**.
- Tap a built tower to select it and see its range and stats.
- **II** pauses the game.

## Known issues / limitations (honest)

1. **Balance:** L1 and L2 are currently easy, and the bot finishes with full HP. This is fine for a tutorial L1, but **L2 is a draft**. All numbers are provisional, and tuning is Phase 4/7.
2. **Input on real devices:** drag and tap are tested with synthetic events and on desktop, **not yet on a phone**. Multi-touch is not handled; the first finger wins.
3. **Layout:** the HUD assumes 1280×720. Wider phones get extra space on the right/bottom. Safe areas/notches and world centring are **Phase 5**.
4. **Not in scope yet:** sell, upgrades, Lance/Beacon, the other enemies, audio, persistence, GameHub integration. The tower info line says "upgrades & selling arrive in Phase 3".
5. **No performance profiling** yet (Phase 7).
6. **Test-runner limitation:** a GDScript runtime error aborts a test without an exception. The runner fails tests with zero assertions, and the log is grepped for `SCRIPT ERROR`.
7. **Not a git repository** yet. No Android/iOS export was attempted (no SDK/templates; no Mac).

## Architectural decisions

- **Controller-driven `step(dt)`** instead of per-node `_physics_process`. Pause is one flag, and tests and balance simulations run thousands of steps synchronously in about a second.
- **Projectiles are pooled data drawn by one canvas item**, not nodes, which means fewer draw calls and no allocation churn.
- **Data `.tres` files are generated** by `tools/author_data.gd` so typed-array serialization is always correct. They are canonical and editable in the editor; note that re-running the tool overwrites them.
- The `EventBus` autoload is deferred until Phase 4 (achievements need it). Nothing uses it yet, so I didn't add an unused abstraction.
